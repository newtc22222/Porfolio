# AGENTS.md

This file provides guidance to AI coding agents working with code in this repository.

## Commands

- `npm run dev`: Vite dev server
- `npm run build`: type-check (`tsc -b`), build the client to `dist/`, build the server entry to `dist-ssr/`, prerender every route (`scripts/prerender.mjs`) and write the share cards (`scripts/build-og.mjs`)
- `npm run lint`: ESLint (flat config in `eslint.config.js`)
- `npm test`: Node's built-in test runner over `src/**/*.test.ts` and `api/**/*.test.ts`
- `npm run preview`: serve the built `dist/`
- `npx prettier --write <files>`: format (single quotes, semicolons, `trailingComma: es5`, 80 cols, with `prettier-plugin-tailwindcss` sorting class names)

Before handing work back, run `npm run build`, `npm run lint`, `npm test` and Prettier. Tests cover only the pure logic (bill split, card queue, status parsing); they import with the `.ts` extension and need no test framework. Everything else is checked by the build, whose prerender step fails if a product is missing from the generated HTML.

## Architecture

This is Phi Vo's personal site, `https://phivo.dev`: the "maker's desk". It is built with React 19, Vite 8, TypeScript and Tailwind CSS v4, and deployed as static files on Vercel plus one small function. The design is in `docs/design/phivo-dev.md`.

- **Routes.** React Router (`src/App.tsx`): `/` is the desk (`src/pages/Desk.tsx`, one scrolling page), `/products/:slug` is a product page (`src/pages/ProductPage`), and anything else is `src/pages/NotFound.tsx`. Every route is prerendered to static HTML at build time: `src/entry-server.tsx` exports `render`, `staticPaths` and `getMeta`, and `scripts/prerender.mjs` writes `dist/index.html`, `dist/products/<slug>.html`, `dist/404.html`, `sitemap.xml` and `robots.txt`. `src/main.tsx` hydrates that HTML (or renders from scratch in `npm run dev`). Per-page title, description and share image come from `src/seo/meta.ts`.
- **Prerender rules.** Anything rendered on the server must not touch `window`, `document` or `localStorage` during render, and must render the same on the server and on the first client render. Use `useIsClient` (`src/hooks`) to hold back browser-only output, and `BUILD_DATE` (`src/lib/buildDate.ts`) instead of `new Date()`. Lazy components render only after hydration.
- **Products are data.** `src/mocks/products.ts` holds one entry per product (type in `src/pages/Products/ProductType.ts`): links, health URL, toy key, screenshots and the story (why, steps, stack, changelog). The home page's hero and Products stop, the product page, the sitemap, the share cards and the status function all read it. To add a product, add an entry; it gets a page and a share card with no other change. This file is also imported by `api/status.ts`, so it may import types only.
- **Toys.** A product's `toy` key points into `src/toys/registry.ts`, which lazy-loads the toy (`src/toys/receipt`, `src/toys/flashcards`). `ToySlot` shows the product's framed screenshot first (that is what the prerendered HTML holds), swaps in the toy when the slot is near the viewport, and keeps the screenshot if the toy fails to load. Toys run on sample data, make no network calls, must work with keyboard and touch, and fill a slot whose size the parent fixes. A product without a toy just shows its screenshot.
- **Home page sections.** In order: `Hero` (`#home`), `Products` (`#products`), `Projects` (`#projects`, "Also on the desk"), `Experiences` (`#experience`, shown as "Work"), `Education`, `Badges` (only when there are badges), `Blog` (`#blog`, shown as "Notes") and `About` (`#about`). Each section is wrapped in a `react-scroll` `<Element name="#id">` with a matching `<section id="id">`. The navbar (`src/layout/Navigation`) builds its links from `NAV_PAGES` in `src/mocks/pages.ts`; off the home page they become router links to `/#id`. When you add, rename or reorder a section, keep `Desk.tsx`, the `Element` name and the `NAV_PAGES` `href` in sync.
- **Other content lives in data files too.** Other projects, blogs, experiences, education, badges and fun facts are plain arrays in `src/mocks/*.ts`. Personal details (name, job title, email, social links, the hero sentence) are in `src/constants/self-information.ts`. There is no Skills section: each role in `experiences.ts` lists its own stack.
- **Status lamp.** `api/status.ts` is a Vercel function that asks each product's `health` URL from Vercel's side and answers `{ slug: 'up' | 'down' }`, cached for a minute. The browser never calls the product APIs. `StatusLamp` (`src/components`) shows "live" or "having a moment", and hides itself whenever the answer is missing or malformed (as in `npm run dev`). The function imports with `.js` extensions on purpose: the package is ESM.
- **Contact.** `Contact` is not a section: it is the form inside the floating bottom-right bubble (`src/layout/ContactBubble.tsx`), which lazy-loads it so EmailJS goes into its own chunk. `openContact()` in `src/layout/contactEvents.ts` opens it from anywhere (the About terminal uses it). The form uses `react-hook-form` with `yup` and sends through `@emailjs/browser`; credentials come from `VITE_EMAILJS_*` env vars (see `.env.example`) and are read in `src/constants/config.ts`.
- **Bundle budget.** The home page's first-load JavaScript should stay at or under 150 KB gzipped. `vite.config.ts` sets manual chunk groups (`vendor`, `emailjs`, `confetti`). If you add a heavy dependency, load it lazily or give it its own group.

## Motion

- Use framer-motion and CSS only. Animate only `transform` and `opacity`.
- Components use framer-motion's light `m` elements (`m.div`, not `motion.div`). `App.tsx` wraps everything in `<LazyMotion strict>` and loads the feature bundle (`src/components/motion/features.ts`) after the first render, which keeps it out of the first-load JavaScript. `strict` makes a stray `motion.*` throw.
- Shared primitives are in `src/components/motion`: `Reveal` (fade and rise on entering view), `Pickup` (a desk object that rests at an angle, lifts on hover or focus, and can be dragged), `Flip`, `Tear`, `ScrollSteps` (a pinned panel that changes per step) and the terminal's `Command` / `Output`. Prefer them to one-off animation.
- Every animation needs a reduced-motion form that shows the end state, and every gesture needs a button or key alternative. `Reveal` and `ScrollSteps` switch in CSS, so the prerendered HTML is correct without JavaScript; `.js` on `<html>` (set by the inline script in `index.html`) marks that JavaScript is running.

## Styling and theming

- The desk is the page surface: use `.desk-surface` and the `desk-*`, `receipt-*` and `card-*` tokens for desk objects. Receipt paper stays pale in dark mode, so its ink token stays dark too.
- Light mode is a low-glare cool grey, not white: use `bg-surface-light dark:bg-surface-dark` for cards, inputs and popovers instead of `bg-white`. Projects and Education have their own section tokens (`projects-*`, `education-*`) in `@theme`. Projects is a gallery wall: each screenshot is framed (`frame-*`, `mat-*`) under a `.picture-light`, with a wall label beside it. Blog is an engineering pad on a blue desk (`blog-*`, `blog-tab-*`): a `.graph-paper` sheet (`src/styles/globals.css`) with topic tabs (`TopicTabs`, a keyboard-navigable tablist with post counts). Experience opens with an overview chart (`Overview.tsx`) that puts jobs, products and side projects on a real time axis parsed from the `period` strings (`period.ts`, format `Mon YYYY - Present`); each role then lists the projects that overlapped it and a collapsible tech stack. About is a terminal session on `term-*` that types itself out once; its timing is computed from the command lengths in `src/pages/About/index.tsx`.
- The site-wide typeface is Bricolage Grotesque (`--font-sans` in `@theme`, loaded from Google Fonts in `index.html` without blocking the first paint). `font-mono` (Martian Mono) is for the About terminal and the receipt toy.
- Tailwind v4 is set up CSS-first through the `@tailwindcss/vite` plugin, and there is no `tailwind.config.js`. The entry point and theme tokens are in `src/App.css` (`@import 'tailwindcss'`, the dark `@custom-variant` and the `@theme` block), which is imported in `src/App.tsx`. Put new colors, fonts and other tokens in that `@theme` block. For accent colors use the `brand` (#4DA8DA) and `brand-2` (#80D8C3) tokens (`bg-brand-2/10`, `var(--color-brand)` in plain CSS) instead of hard-coded hex values or Tailwind `blue-*` classes. For accent-colored text on light backgrounds use `text-brand-strong dark:text-brand-2`, because #4DA8DA on white fails WCAG contrast. `src/styles/globals.css` (imported in `src/main.tsx`) and `src/index.css` contain only extra plain CSS.
- Dark mode uses a custom variant tied to `[data-theme=dark]` on `<html>`, not the `prefers-color-scheme` media query. `ThemeToggle` sets that attribute and saves the choice to `localStorage`. Style components with paired tokens, such as `text-primary-light dark:text-primary-dark` and `bg-background-light dark:bg-background-dark`.
